# snake-gbc

A size-minimal Snake game for the Game Boy Color that runs entirely from
internal RAM. After boot, the game copies itself into WRAM and never touches
the cartridge again, so the cartridge can be removed while the game keeps running.

- Game code: **386 bytes** (plus an 18-byte ROM loader)
- ROM file: 32 KB (the smallest standard cartridge size; the rest is padding)
- CGB-only (header flag `$C0`)

## Build

Requires [RGBDS](https://rgbds.gbdev.io/) ≥ 1.0.

```sh
make            # -> snake.gbc (standalone ROM)
make snake.bin  # -> the $C000 payload for the homebrew loader (403 B)
make clean
```

## Run

Any GBC emulator or flash cart works, for example:

```sh
vba snake.gbc     # VisualBoyAdvance: arrow keys to steer, Esc to quit
bgb snake.gbc     # BGB: more accurate CGB emulation
```

## Gameplay

- Use the D-pad to steer. Reversing straight into yourself is ignored.
- The snake starts 3 segments long, moving right, on a walled 18×16 field.
- Eating food (red) grows the snake by one segment and speeds it up, from one
  step every 10 frames down to a minimum of every 3 frames.
- Hitting a wall or yourself causes a pause of about 1.5 s and then a restart.
- Launched from the homebrew loader (`snake.bin`), **SELECT** returns to the
  loader's menu at any time (checked every frame in `WaitVBlank`; not shown on
  screen). The standalone `snake.gbc` (`-DSTANDALONE`) has no loader to return
  to and ignores SELECT.

## How it runs without the cartridge

| Concern | Solution |
|---|---|
| Code lives in ROM | `Loader` (at `$0150`) copies the payload to `$C000` and jumps there. The payload is written as an RGBDS `LOAD` block, so its labels resolve to WRAM addresses. |
| Interrupt vectors are in ROM (`$0040`…) | Interrupts are never enabled (IME = 0). `IE` = VBlank only, and `halt` wakes on VBlank without jumping to a vector. `IF` is cleared before each `halt` to avoid the HALT bug. |
| Graphics data | Tiles are generated by code (solid colored squares with a 1 px gap). The palette is stored inside the payload. |
| Randomness | An 8-bit LCG (`x*5+1`) XORed with `DIV`. |
| Variables / stack | Variables are in HRAM (`$FF80`…). The stack stays where it was: the boot default in HRAM, or the loader's in WRAM bank 7 (a few bytes, which the loader tolerates on SELECT). |

## Memory map

| Address | Contents |
|---|---|
| `$C000–$C181` | Game code + data (copied from ROM); `$C000–$C192` in the payload build (+ the SELECT check) |
| `$C400–$C7FF` | Shadow of the 32×32 BG map |
| `$8000–$806F` | 7 generated tiles |
| `$9800–$9BFF` | BG map (bank 0), attributes cleared to 0 (bank 1) |
| `$FF80–$FF88` | `hHead`, `hTail`, `hDir`, `hNext`, `hTimer`, `hSpeed`, `hRng` |

## Design notes

**Shadow map equals tile map.** Each cell value in the WRAM shadow is also the
tile index written to VRAM:

| Value | Meaning |
|---|---|
| 0 | empty |
| 1 | wall (also fills the off-screen part of the 32×32 map) |
| 2 | food |
| 3–6 | snake body; `value − 3` = direction toward the next segment |

Game logic reads only the shadow map, never VRAM. Because the snake's
direction is stored in the cells themselves, no position queue is needed: when
the head moves, the old head cell records the move direction, and the tail
reads its own cell to find where to go next.

**Directions** are `0 right, 1 left, 2 up, 3 down`, which is the bit order of
the joypad's D-pad nibble. The first pressed direction is simply the index of the
lowest set bit, and the opposite direction is `dir xor 1`. Map offsets come from
`Offsets` (`+1, −1, −32, +32`).

**VRAM writes** go through `PutTile`, which updates the shadow and then waits
until STAT mode is 0 or 1 before writing, so it is safe at any point in the
frame. Full redraws (start and restart) happen with the LCD off.

**Food placement** picks random 10-bit offsets into the shadow map until it
finds an empty cell. Because everything outside the playfield is marked as wall,
no bounds check is needed. (If the board were completely full this would loop
forever, which is effectively unreachable.)

## Caveats

- Pulling a cartridge out of a running console can cause a brief power dip
  that resets or crashes some units. The software never accesses the cartridge
  after boot, but survival of the hot-pull depends on the hardware. Remove the
  cartridge in one clean motion.
- There is no score display.
- Moving into the cell the tail is just leaving counts as a collision.
